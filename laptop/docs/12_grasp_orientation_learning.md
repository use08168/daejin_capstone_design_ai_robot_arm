# 파지 방향 문제와 접근 조건부 학습 — 형상에 따라 수직/수평을 어떻게 결정하는가

> **요지:** 그리퍼가 물체를 *잘* 잡으려면 **위치**만이 아니라 **접근 방향(수직 top‑down / 수평 side)** 과
> 손목 방향(J4~J6, 특히 J6=수평 피치)이 **물체 형상·바닥 여유에 맞게** 정해져야 한다. 현재 파지
> 데이터는 접근 방향이 섞여 있어 자세 예측이 부정확하고, 형상에 따른 접근 선택이 데이터에 명시돼
> 있지 않다. 해결: **접근 타입(수직/수평)으로 데이터를 구조화**하고, 물체 형상 + 3D 좌표로 **접근
> 타입 자체를 학습으로 결정**한다.

관련: [11_gripper_design.md](11_gripper_design.md) · [9_grasp_pipeline.md](9_grasp_pipeline.md) · [6_digital_twin_safety.md](6_digital_twin_safety.md)

## 2. 도달한 문제

### 2.1 자세 회귀가 부정확한 진짜 이유 — 다봉성 + 접근 방향 혼재
관절각 회귀 MAE가 37°로 크다(J1=24°는 작고 손목 J4~J6=43~46°가 큼). 원인:
- **다봉성(multi‑modal):** 같은 물체를 잡는 유효 자세가 **여러 개**다(여러 방위각·롤). 데이터는 그중
  하나(최적)만 기록하므로, 회귀가 여러 해의 평균으로 뭉개진다.
- **접근 방향 혼재:** 현재 데이터는 수직(221)·수평(892)·기타(444)가 **한 모델에 섞여** 있다. 수직과
  수평은 손목 자세가 근본적으로 달라, 섞으면 더 뭉개진다.

> 결론: "물체 → 관절각"을 한 모델로 직접 예측하는 건 부적절하다. **접근 타입을 먼저 가르고**, 타입
> 안에서 자세를 풀어야 한다.

### 2.2 접근 방향은 형상·바닥에 종속된다
- **키 큰 원기둥(R15·H60):** 옆에서 **수평** 접근 → 중심을 감싸 안정적.
- **납작한 원기둥(R15·H10):** 수평 접근하면 **로봇팔이 바닥과 충돌** → 위에서 **수직** 접근해야 함.
- **베이스에 가까운 물체:** 팔이 접히지 못해 수평이 어렵고 **수직**이 유리.

즉 *어떤 위치·형상이냐*에 따라 가능한 접근이 갈린다. 이게 데이터·모델에 **명시적으로** 들어가야 한다.

### 2.3 방향이 안 맞으면 그리퍼가 물체를 "밀어버린다"
접근축·롤(J4~J6)이 물체와 어긋나면, 손가락이 양쪽을 감싸지 못하고 물체를 옆에서 밀거나 한쪽만
닿는다(헛잡음). 접촉 검출(C)이 이를 잡아내지만, **올바른 손목 자세를 데이터가 충분히 담아야** AI가
밀지 않고 감싸는 자세를 학습할 수 있다.

## 3. 해결 방향 (합의)

### 3.1 접근 타입으로 데이터를 구조화 — 타입 고정, 내부 최적화
접근을 두 타입으로 나누되, **타입만 제약하고 그 안의 자유도는 도달성·접촉품질로 최적화**한다.

| 타입 | 그리퍼 방향 | 내부 자유도(최적화) |
|------|-------------|---------------------|
| **수직(top‑down)** | 접근축 = 정아래(−Y) | 원형 단면은 롤 자유, 박스는 롤이 단면에 정렬 |
| **수평(side)** | 접근축 = 수평, 물체 중심을 향함 | **방위각(어느 쪽에서 접근)** + **롤(손가락이 물체를 감싸게)** |

> 타입을 고정하면 팔이 그 방향을 맞추려고 **J4~J6를 의미있게 움직인다**(원했던 "J6가 코디네이션되어
> 움직임"). 동시에 내부 최적화로 **도달 반경 손실을 최소화**한다. (완전 고정 방식은 더 단순하지만
> 반경이 더 줄어 비채택.)

### 3.2 바닥/자기 충돌은 자동 라벨 → 납작 물체는 수직
데이터 생성 시 이미 바닥·자기 충돌을 검사한다(`floor_clear`). 납작 물체의 수평 접근은 자연히 충돌로
라벨돼 제외되고, 수직만 남는다. **별도 규칙 없이 물리로 걸러진다.**

### 3.3 접근 결정도 "처음부터 학습"
수직/수평 선택을 휴리스틱이 아니라 **데이터로 학습**한다. 이를 위해 데이터 생성 시 **물체마다 수직·수평을
둘 다 시도해 각각 라벨**한다(성공/실패·품질). 그래야 모델이 "이 형상·위치엔 수직이 되고 수평은 안 됨"
같은 경계를 직접 배운다. 핵심 입력 특징: 물체 **형상(type)·반경 R·높이 H·3D 위치(x,y,z)**.

### 3.4 결과물 — 두 개의 capability map + 접근 선택기
- **수직 파지가능 맵** / **수평 파지가능 맵**(각 타입의 도달+충돌+접촉 검증 영역)
- **접근 선택기**(물체 형상·위치 → 수직/수평/불가)

## 4. 런타임 그림 (목표)

```
비전(캘리브레이션 3D 좌표 + 형상 R·H·type)
        │
        ▼
 [접근 선택기]  물체 형상·위치 → 수직? 수평? (둘 다 가능하면 더 안정적인 쪽)
        │
        ▼
 [해당 capability map]  그 타입으로 도달·충돌없이 잡을 수 있는가 → 파지 자세
        │
        ▼
 [IK/검색 미세보정] 접근축·롤을 접촉검출(C)이 ✅ 줄 때까지 정렬 → 실행(J1~J6, J7 개폐)
```

분류기(파지 가능?)는 **즉시 판단(검증층)**, 정밀 자세는 **타입 내부 검색**으로 보정. 다봉성은 "여러 해 중
도달·충돌·접촉이 가장 좋은 하나"를 검색이 고르게 두어 해소한다.

## 5. 트레이드오프 · 남은 과제

- **반경 축소:** 타입을 제약하면 임의 방향보다 도달 반경이 준다 — 의도된 trade‑off(신뢰성 ↑).
- **형상별 중요 자유도:** 원형 단면은 수직 시 롤 자유, 박스·납작은 롤이 중요 → 형상별로 자연히 데이터에 반영.
- **데이터 재생성 필요:** 현재 `grasp_learn.csv`는 접근 혼재. **수직/수평을 물체마다 둘 다 시도·라벨**하는
  방식으로 재생성해야 한다(1단계 도구 수정).
- **접근 선택기 학습:** 형상·위치 → 수직/수평/불가 분류. 둘 다 가능 시 안정성(키·바닥여유) 기준 선택.
- **실물 검증:** 시뮬에서 검증된 접근·자세가 실물에서도 물체를 감싸는지(접촉 ≥2점) 확인 → sim‑to‑real.

## 6. 한 줄 요약

> 파지는 "어디"만이 아니라 **"어느 방향(수직/수평) + 어떤 손목 자세"** 의 문제다. 형상·바닥이 접근을
> 결정하므로, **접근 타입으로 데이터를 나눠 생성하고, 접근 선택을 학습**해야 그리퍼가 밀지 않고 감싼다.
