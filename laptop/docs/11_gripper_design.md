# 그리퍼 정밀 설계 — 평행집게 개폐 시뮬레이션과 sim-to-real 신뢰성

> **요지:** 파지 데이터셋(10만 세트)이 주는 것은 "도달 가능 + 충돌 없음"인 **접근 자세**일 뿐,
> 그 자세에서 그리퍼가 **실제로 물체를 잡는지**는 보장하지 않는다. 이를 시뮬레이터에서 검증하려면
> 그리퍼의 **개폐 기구(평행집게 손가락의 병진 운동)** 를 정확히 모델링해야 한다. 그래야 손가락이
> 닫힐 때 가상 물체와 **양쪽에서 접촉(antipodal ≥2점)** 하는지 판정할 수 있고, 비로소 시뮬 파지
> 데이터를 **실물에 신뢰성 있게** 쓸 수 있다. 이 문서는 *왜* 그리퍼를 이 정도로 디테일하게 만들었는지와
> *어떻게* 구현했는지를 정리한다.

관련: [9_grasp_pipeline.md](9_grasp_pipeline.md) · [8_arm3d_simulator.md](8_arm3d_simulator.md) · [6_digital_twin_safety.md](6_digital_twin_safety.md)

## 1. 왜 그리퍼를 디테일하게 만들었나 (설계 근거)

### 1.1 핵심 목표 — "시뮬 데이터를 현실에서 그대로 쓴다"

이 프로젝트의 파지 전략은 [9_grasp_pipeline.md](9_grasp_pipeline.md)의 **FK 샘플링 파지 DB**다.
디지털 트윈(arm3d)에서 관절각을 무작위로 샘플링해 `[관절각 → 그리퍼 TCP 포즈 + 접근벡터 + 충돌라벨]`을
10만 세트 기록하고, 이를 역질의해 "물체 위치 + 접근 방향 → 충돌 없는 관절각"을 얻는다.

그런데 이 데이터의 한 행이 보장하는 것은 다음 뿐이다:

- ✅ 그 관절각이 **운동학적으로 도달 가능**하다
- ✅ 그 자세에서 팔이 **바닥/자기 자신과 충돌하지 않는다**

**보장하지 않는 것:** 그 자세에서 그리퍼를 닫았을 때 **물체를 실제로 움켜쥐는가**.
손가락이 물체를 비껴가면(헛잡음) 도달 가능·충돌 없음이어도 파지는 실패한다.
즉 데이터셋만으로는 "접근 자세"일 뿐 "검증된 파지"가 아니다.

> **그래서 그리퍼 개폐를 시뮬에 넣는다.** 손가락이 닫히는 기구를 정확히 모델링하면, 각 후보 자세에서
> **실제 닫힘 동작을 시뮬레이션**해 손가락-물체 접촉을 판정할 수 있다. 이 검증을 통과한 행만 남기면
> 데이터셋이 "검증된 파지 DB"가 되어 **실물 신뢰성**이 올라간다. 이것이 sim-to-real의 핵심 다리다.

### 1.2 왜 "평행집게(prismatic)"를 정확히 모델링해야 했나

초기에는 손가락을 **회전(pivot) 관절**로 가정했으나, 실제 하드웨어는 두 손가락이 서로 마주 본 채
**미끄러지는(병진, prismatic) 평행집게**다. 이 차이는 접촉 판정에 직접 영향을 준다:

- 회전 모델은 손가락 끝이 호(arc)를 그리며 접촉점·접촉각이 물체 크기에 따라 달라진다.
- 병진 모델은 두 접촉면이 **평행하게 마주 보며 좁혀져**, antipodal 접촉(마주 보는 2점)이 기하학적으로
  명확하다. 파지 안정성(force-closure) 판정과도 일치한다.

따라서 그리퍼를 **프리즈매틱 슬라이드**로 정확히 구현하는 것이, 1.1의 접촉 검증을 신뢰성 있게
만드는 전제 조건이었다.

### 1.3 J7과의 연결 — 시뮬 개폐 = 실물 서보 한 채널

실물 그리퍼는 서보 1개(채널 **ch6**, J7)로 개폐한다(열림 ~550µs, 닫힘 ~2500µs).
시뮬의 개폐 파라미터 `t`(0=열림, 1=닫힘)를 이 펄스 폭에 선형 매핑하면, **시뮬에서 검증한 개폐량을
그대로 실물 명령으로** 보낼 수 있다. 시뮬과 실물이 같은 1-DOF 개폐 모델을 공유하는 것이다.

## 2. 어떻게 구현했나 (기구 모델)

### 2.1 결합(mate) 타입에 "그리퍼(grip)" 추가

arm3d의 리깅은 **면결합(mate)** 으로 부모-자식 관절을 만든다([8_arm3d_simulator.md](8_arm3d_simulator.md)).
기존 타입은 **회전(rev)** 과 **고정(fix)** 두 가지였고, 여기에 세 번째 타입 **그리퍼(grip)** 를 추가했다.

| 타입 | 운동 | `applyAngles` 적용 |
|------|------|---------------------|
| `rev` | 회전 | `pv.quaternion = axisAngle(axis, angle−90°)` |
| `fix` | 고정(강체) | 변환 없음 |
| **`grip`** | **병진(슬라이드)** | **`pv.position = base + axis · slide`** (mm) |

손가락 부품(`r→f.1`, `r→f`)을 grip 타입으로 결합/전환(`toGrip` 버튼)한다. 두 손가락은 서로 마주 보며
각자의 슬라이드축을 따라 좁혀진다.

### 2.2 슬라이드축은 그리퍼 로컬 프레임 (자세 따라 회전)

슬라이드 방향 `axis`는 **그리퍼 부모 그룹(pg)의 로컬 프레임**에 저장된다. `pv`(슬라이드 피벗 그룹)는
`pg`의 자식이므로, 손목 관절(J6 등)이 회전하면 `pg`가 회전하고 슬라이드축도 함께 회전한다.
→ **팔이 어떤 자세든 손가락은 항상 그리퍼가 향한 방향으로 곧게 개폐**된다.

축 보정 도구(관절 편집의 **축기울기 / 축위치**)와 **슬라이드축 시각화**(파란 z축 triad + 노란 선)로
손가락이 옆(개폐) 방향으로 미끄러지도록 정렬한다.

### 2.3 개폐 보정 — gOpen / gClose

손가락마다 **완전 열림**과 **완전 닫힘**에서의 슬라이드값을 저장한다(`gOpen`, `gClose`).
이후 `setGripper(t)`가 `slide = gOpen + (gClose − gOpen)·t` 로 두 손가락을 동시에 구동한다.
두 손가락이 반대 방향으로 좁혀지도록 각자 자신의 열림/닫힘 값을 따로 캡처한다.

### 2.4 제어 모드 J7 컨트롤

3D 제어(연동) 모드의 관절 슬라이더 아래에 **J7 · 그리퍼** 개폐 슬라이더를 둔다:

- 슬라이더(0% 열림 ↔ 100% 닫힘) → `setGripper(t)`로 3D 손가락 구동
- 연동(sync) ON + 실물 연결 시 → **ch6** 에 `550 + (2500−550)·t` µs 전송
- 개폐 보정이 안 됐으면 경고 카드로 결합 모드 보정을 안내

## 3. 안정성 엔지니어링 — 리깅 드리프트 제거

그리퍼를 결합 과정에서 직접 설정하면서, **재리깅(rebuild)이 현재 자세를 기준점에 구워 넣어** 값이
누적 이동하는 버그가 여러 곳에서 드러났다. 공통 원인과 해결은 다음과 같다.

> **공통 원인:** `rebuild()`는 부품을 평면화한 뒤 다시 리깅하면서, 슬라이드 피벗의 기준점(`_base`)을
> **그 순간의 자세** 기준으로 계산한다. 비휴식(슬라이드·회전된) 상태에서 rebuild가 일어나면 기준점이
> 어긋나 드리프트/대각선 슬라이드가 생긴다.
>
> **공통 해결:** **항상 휴식 자세(회전=90°, 그리퍼=슬라이드 0)에서 리깅**한다.

| 증상 | 트리거 | 수정 |
|------|--------|------|
| 축기울기/축위치 시 위치·보정값 누적 이동 | 조정 전 비휴식 상태로 rebuild | 조정 전 `_restFlatten()`(전 관절 휴식 + 평면화) |
| 저장 시 손가락 STL이 멀리 밀림 | 저장이 grip 휴식을 90°(=슬라이드 90mm)로 리셋 | 휴식 리셋을 grip=0으로 |
| 저장해도 개폐 보정이 사라짐 | 직렬화에 `gOpen`/`gClose` 누락 | 직렬화에 추가(로드는 `saved.mates` 직접 복원) |
| 결합/제어 진입 시 손가락 튐 | 모드 진입 rebuild가 stale 슬라이드 적용 | 진입 시 grip=0, rev=90으로 리셋 후 rebuild |
| 자세 잡고 개폐 시 대각선 이동 | 포즈 상태에서 rebuild되어 `_base` 어긋남 | 제어 진입도 휴식 자세에서 리깅 |

이 수정들로 **축 보정 → 개폐 저장 → 저장/재로드 → 어떤 자세에서든 개폐**가 일관되게 동작한다.

## 4. 다음 단계 — 손가락-물체 접촉 검출 (파지 검증)

그리퍼 개폐가 정확해졌으므로, 1.1의 목표인 **접촉 검증**을 구현한다:

1. 가상 물체(원기둥/구/컵 등, [9_grasp_pipeline.md](9_grasp_pipeline.md)) 옆에서 `setGripper(t)`로 닫는다.
2. 각 손가락 메시 ↔ 물체 표면의 **접촉/관통**을 검출한다.
3. **양쪽에서 ≥2점 접촉(마주 보는 면)** = ✅ 유효 파지. 한쪽만/없음 = ⚠️ 헛잡음, 관통 = ⚠️ 충돌.
4. 이 판정을 파지 데이터셋 각 후보에 적용 → **검증된 파지만 남긴 DB** → 실물 신뢰성 확보.

이후: 놓기(place) 시퀀스 · 그리퍼 실제 폭 제어 · 실물 검증 · SAM 3D Objects 연동.
