# 객체 탐지 모델 선택 명세 — YOLO-World

> 노트북 비전 계층의 **실시간 객체 탐지 모델** 선택 근거와 설정을 기록한다.
> 결론: **Ultralytics YOLO-World (yolov8m-worldv2)** — 오픈 보캐뷸러리 탐지.
> 구현: `armvision/detector.py`

## 2. 왜 "오픈 보캐뷸러리"인가 (핵심 근거)

### 2.1 아키텍처 정합성
시스템 설계상 **노트북은 "물체가 어디 있는지"만 찾고**, "그게 무엇인지"의 최종 판단은
**AI 서버(Gemma VLM)** 가 한다. 따라서 노트북 탐지기는 분류 정확도보다
**탐지 커버리지(있는 물체를 빠짐없이 잡기)** 가 중요하며, 특정 클래스에 묶이지 않는
**class-agnostic / 오픈 보캐뷸러리** 방식이 맞다.

### 2.2 닫힌 어휘(COCO) 모델의 한계 — 실측으로 확인
처음엔 COCO 80클래스 모델(YOLO11)로 시작했으나, 실제 작업대 물체에서 문제 발생:

| 물체 | COCO 모델 결과 |
|------|---------------|
| 스프레이 병 | bottle 로 잡힘 (OK) |
| 포카리 캔 | 각도에 따라 누락 (COCO에 'can' 없음 → 'bottle'로 애매) |
| 커터칼 | 거의 못 잡음 (COCO 'knife'는 주방칼) |
| 멀티탭 | 'remote'로 오인 또는 누락 |

→ **이는 모델 "성능"이 아니라 "어휘(클래스)" 문제.** 모델을 키워도(yolo11x, RF-DETR,
YOLO26 모두 COCO 기반) 동일하게 못 잡는다.

### 2.3 YOLO-World 의 해결
`set_classes([...])` 로 **찾을 물체 이름(자연어)** 을 지정하면 그것을 탐지한다.
→ can, cutter knife, power strip 등 COCO에 없는 물체도 프롬프트로 포착. 실측에서
좌/우 카메라 모두 캔·커터칼·멀티탭이 잡히는 것을 확인.

## 3. 검토한 후보 비교 (RTX 3050 GPU 실측)

| 모델 | 어휘 | GPU 속도 | 비고 |
|------|------|---------|------|
| yolo11n (COCO) | 닫힘 80 | 11ms | 비전 시작점, 비COCO 물체 누락 |
| yolo11m (COCO) | 닫힘 80 | 22ms | 커지면 정확↑지만 어휘 한계 동일 |
| **yolov8s-worldv2** | **오픈** | 11ms | 가벼움 |
| **yolov8m-worldv2** | **오픈** | **19ms** | ✅ **채택 (속도·정확 균형)** |
| **yolov8x-worldv2** | **오픈** | 45ms | 최고 정확, 2카메라 동시엔 ~11fps |
| yolo26n / yolo26s | 닫힘 80 | 21 / 31ms | 최신·효율적이나 `set_classes` 미지원 → 어휘 한계로 부적합 |

> 참고: GPU 적용 전 CPU 추론은 yolo11n 기준 ~227ms(≈4fps)로 매우 느렸음.
> CUDA torch(cu124) 설치 후 ~20배 향상. → GPU 사용이 사실상 필수.

### 3.1 YOLO26 을 안 쓴 이유
YOLO26은 닫힌 어휘(COCO 80) 탐지기로 `set_classes`를 지원하지 않는다. 빠르고
효율적이지만, "임의 물체 탐지" 목적엔 §2.2의 한계로 되돌아가므로 채택하지 않음.

### 3.2 RF-DETR 을 (현 단계에서) 안 쓴 이유
시스템 사양서의 장기 선택지이나, COCO 기반이라 어휘 한계가 같고 4GB VRAM엔 더
무겁다. 파이프라인을 YOLO-World로 먼저 완성하고, 필요 시 교체 가능(탐지 인터페이스
동일 유지).

## 4. 설정 / 사용법

### 4.1 프롬프트 클래스 (`detector.py` 의 `PROMPT_CLASSES`)
찾을 물체 목록. **이름만 추가/삭제하고 서버 재시작**하면 반영. 자연어 명사구 가능
(예: `"blue spray can"`).

```python
PROMPT_CLASSES = [
    "spray bottle", "bottle", "can", "cup",
    "cutter knife", "knife", "scissors", "pen", "marker",
    "power strip", "book", "box", "remote control", "hand",
]
```

### 4.2 동시성
두 카메라 스레드가 **같은 모델 인스턴스를 공유**하므로 추론은 `threading.Lock` 으로
직렬화한다(스레드 안전). VRAM 절약 + 안정성.

### 4.3 신뢰도
오픈 보캐뷸러리는 점수가 낮게 나와 임계값을 **0.10** 으로 둠. 오탐이 많으면
`_DEFAULT_CONF` 를 0.15~0.2 로 상향.
