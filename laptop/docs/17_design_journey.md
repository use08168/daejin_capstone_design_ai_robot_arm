# 17. 파지 학습·실행을 만들며 한 고민 (Design Journey)

> 📂 [루트](../../README.md) → [laptop](../README.md) → [laptop/docs](README.md) → **17 (고민 기록)**

> **이 문서의 목적.** 다른 문서들이 "무엇을 만들었나(결과)"를 명세한다면, 이 문서는 **"왜 그렇게 결정했나, 무엇이 막혔고 어떻게 풀었나"**를 시간 순서로 남긴다.
> 똑같은 고민을 반복하지 않기 위한 의사결정 로그다. 결론만 보려면 각 절의 **▶ 결정**을 읽으면 된다.

---

## 1. "물체를 잡는 법"을 어떻게 학습시킬 것인가 — Physical AI vs. C-space식 학습

**고민.** 가상의 물체를 두고 자동으로 잡게 하고 싶었다. 그런데 요즘 화제인 Physical AI(대규모 시뮬·강화학습·foundation model)를 써야 하나? 우리 장비(RTX 3050 4GB)로 가능한가?

- Physical AI/RL: 강력하지만 대규모 시뮬·GPU·sim-to-real 튜닝이 필요. 캡스톤 범위·장비를 초과.
- 우리가 이미 **디지털 트윈 C-space 충돌지도**를 신경망으로 학습한 경험([6_digital_twin_safety.md](6_digital_twin_safety.md))이 있다 — "공간을 샘플링해 라벨을 만들고 MLP로 일반화"하는 패턴.

**▶ 결정: L1 파지 학습(C-space식).** 시뮬레이터가 스스로 파지를 시도→접촉/충돌로 자동 라벨링→그 데이터로 MLP가 "이 물체를 이 접근으로 잡을 수 있나"를 일반화. 무거운 RL 없이, 우리가 잘하는 방식의 연장선. → [12_grasp_orientation_learning.md](12_grasp_orientation_learning.md), [13_grasp_learning_mlp.md](13_grasp_learning_mlp.md).

---

## 2. 무엇을 학습시킬 것인가 — 방향(수직/수평)이 핵심이었다

**고민.** 물체를 "잡을 수 있다/없다"만으로는 부족했다. 같은 컵이라도 **위에서 수직으로** 잡을지, **옆에서 수평으로** 잡을지가 물체 형상·바닥 안착 여부로 갈린다. J6 관절 각도에 따라 노란 면(파지면)이 수평이어야 수직으로 잡힌다는 걸 시각화로 확인.

**▶ 결정: 접근 조건부 학습.** 입력 특징에 `approach`(수직/수평)를 넣고, 한 물체에 대해 **두 접근 모두** 데이터를 생성. 출력은 ①파지 가능 여부(분류) ②품질(회귀) ③접근 선택(argmax). 물체는 바닥에 안착시켜 형상 효과가 반영되게.

---

## 3. 데이터가 계속 거짓말을 했다 — 라벨링 신뢰성과의 싸움

가장 길게 싸운 부분. 데이터셋이 그럴듯한데 **틀린** 라벨을 만들어내는 일이 반복됐다.

| 증상 | 진짜 원인 | 교훈 |
|------|----------|------|
| 성공률 0.5%, 데이터에 perp~227mm | `applyAngles()`는 로컬 변환만 갱신, **월드 행렬 미갱신**(동기 루프엔 렌더가 없음) → 손가락이 rest pose에 멈춤 | 동기 평가 루프에선 반드시 `rigRoot.updateMatrixWorld(true)` |
| 성공률 99% (음성 샘플 거의 없음) | 양성 위주 샘플링 | 음성도 **넓게/전역** 샘플링해야 분류기가 경계를 배움 |
| 큰 물체(R150+)가 오히려 99% 성공(거꾸로) | jaw 판정이 **그리퍼 개폐 한계를 무시**, perp 임계가 R에 비례 | 실측(지름 50mm까지) → `2R ≤ glGrip` 게이트 + 고정 임계 |
| 충돌 미검출(물체가 팔 안에 있는데 유효) | 라벨링이 **물체-팔 충돌**을 안 봄 | 라벨에 충돌 검사 필수 → `_bodyHitsObject`/`_gripperHitsObject` |

**▶ 결정/교훈.** "**데이터가 곧 모델**"이다. MLP를 의심하기 전에 라벨링 시뮬을 의심하라. 특히 (a) 월드 행렬 동기화, (b) 양·음성 균형, (c) 물리 제약(개폐 폭)의 실측 반영, (d) 충돌까지 포함한 유효성 — 이 넷이 갖춰져야 데이터가 진실을 말한다. 사용자가 "grasp_dataset 자체에 문제가 있어 보인다"고 짚은 게 정확했고, P1 파지 DB를 충돌 인식으로 재생성(30만→100만)했다.

## 4. "유효 파지까지는 가는데 자세가 엉성하다" — 학습 한계인가 구조 한계인가

**고민.** 최적 자세 찾기로 잡으면 잘 잡을 것 같은데 수직/수평이 깔끔하지 않다. 이게 **MLP 학습의 한계**인가, 아니면 **로봇팔의 구조적 한계**인가? 이 둘을 구분 못 하면 엉뚱한 곳(데이터만 더, 또는 팔만 탓)을 고치게 된다.

**▶ 결정: 접근 가능 구역 맵(🗺)으로 구조를 먼저 본다.** 특정 크기 물체(R15·H30)로 워크스페이스 전체를 격자 스캔해 각 위치에서 수직/수평 도달 기울기를 측정·시각화. 결과는 명확했다 — **도달 영역이 환형**이고 **베이스 근접부는 수직 파지 사각지대**. 즉 일부는 **팔의 기구학적 한계**(MLP 잘못이 아님)였다.

**교훈.** 학습 모델을 디버깅하기 전에 **물리적으로 가능한 영역**을 측정하라. "할 수 있는 만큼" 정렬하고 남은 기울기를 숫자로 보여주는 방식(`tilt=angErr`)으로, 한계를 숨기지 않고 드러냈다.

---

## 5. 어떻게 접근할 것인가 — 한 번에 vs. 두 단계(standoff→직선)

**고민.** 물체로 바로 IK를 풀면 노란 면이 꺾인 채 비스듬히 들어가 측면을 치거나 밀어낸다. 사용자 제안: **jaw의 x축을 물체 축과 먼저 정렬하고, 2단계에서 그 축을 따라 똑바로 내려가자**(수평도 동일).

후보를 두 가지로 정리해 논의했다:
- (a) 한 자세로 한 번에 — 단순하지만 정렬·간섭 제어가 어려움.
- (b) **standoff에서 정렬 → 직선 접근** — 프리그래스프에서 자세를 맞추고 접근축으로만 직진. 6-DOF 파지 문헌의 표준(approach vector + pre-grasp standoff).

**▶ 결정: (b) 두 단계.** `executeGraspTwoStage`. 막히면 직접 접근으로 폴백. → [16 §2](16_grasp_place_runtime.md).

---

## 6. 잡았으면 놓아야 한다 — 놓기 프로세스와 좌표 추적

**고민.** Gemma와 연동하면 "이 물체를 저기에 놓아줘"가 된다. 그러려면 **놓기(place)**가 집기와 짝을 이뤄야 한다. 그런데 구현하니 문제가 줄줄이 나왔다.

- 물체를 옮겨도 **놓기 IK 목표 좌표가 안 움직임** → `_updateHeld`가 ikX/Y/Z를 든 물체로 갱신.
- 놓기 좌표가 xz뿐이라 **물체를 공중에** 둠 → `plY` 입력 추가.
- 운반 중 **바닥을 쓸며** 감 → 들어올림→운반→하강 4스텝 + 운반 높이 여유.

**▶ 결정.** 집기·놓기를 **한 쌍의 원자 동작**으로 설계. 물체는 닫는 순간 강체 부착(`_held`), 매 프레임 TCP를 따라가고, 놓기 좌표·높이를 명시적으로 받는다.

---

## 7. 놓을 때 물체가 기운다 — J6 자이로

**고민.** 놓기는 되는데, 보니 **J6를 충분히 돌릴 수 있는데도 덜 돌려** 운반 중 jaw(물체)가 기운다. 수평 상황에서 jaw의 xz를 유지해야 물체를 안전하게 내려놓는다.

**원인.** IK 비용이 **위치 위주**라 자세가 뒷전 → 위치만 맞추고 손목을 덜 회전.

**▶ 결정: 자세 가중치 손잡이 `ow` + 레벨링.** `_ikToPose`에 `ow`를 노출(기본 1.5), 놓기에선 `ow=4`로 자세를 강하게 유지. 접근이 수평이면 손가락축을 수직으로 재정렬(레벨링)해 노란 면을 수평으로 고정. → J6가 "충분히" 돌아 물체가 수평을 유지. → [16 §4](16_grasp_place_runtime.md).

---

## 8. 일관되게 지킨 원칙

- **작은 단위로, 하나씩 검증.** 큰 리팩터 대신 증상→원인→최소 수정→확인을 반복. (incremental fast workflow)
- **도구가 섞이면 정리부터.** 버튼/도구가 많아질 때마다 역할을 갈라 정리(🧠 주파지·🎯 단일최적·🗺 진단·📥 놓기).
- **문헌에 근거를 둔다.** 손목 roll 최적화·approach 샘플링은 GraspNet/Dex-Net 등 6-DOF 파지 생성 연구에 맞춤([13 §9](13_grasp_learning_mlp.md)).
- **한계를 숨기지 않는다.** 도달 못 하면 기울기°·거부 사유를 그대로 표시 → 사용자가 구조 한계와 버그를 구분할 수 있게.

---

## 9. 남은 고민(다음 차례)
- **AI 서버 연동.** Gemma DSL `[pick, place]` ↔ 시뮬 원자 동작. 자연어·음성에서 물체 id/목표로의 번역.
- **물체 자세 부착.** 현재는 위치만 부착 — 회전까지 들고 옮기면 더 일반적인 놓기가 된다.
- **실물 적용.** 시뮬에서 검증한 시퀀스를 실제 서보로. sim-real gap·접근 가능 구역 안에 물체 배치 전제.
