# 시스템 아키텍처

> 본 문서는 전체 시스템의 3계층 분산 구조와 각 계층의 책임 경계를 정의한다.
> 세부 인터페이스는 [gRPC 명세](grpc_interface.md), [Serial 명세](serial_protocol.md), [DSL 명세](dsl_spec.md) 참조.

---

## 1. 3계층 분산 구조

```
┌─────────────────────────────────────────────────────┐
│  Layer 3: AI 서버 (MSI EdgeXpert)                    │
│  - Whisper Large-v3 (한국어 STT)                     │
│  - Gemma 4 (멀티모달 LLM/VLM)                        │
│  - Qwen3-Embedding-8B (RAG)                          │
│  - FAISS Vector DB                                   │
│  - 역할: "무엇을 할지" 결정                            │
└─────────────────────────────────────────────────────┘
                        ↕ gRPC + Protobuf
┌─────────────────────────────────────────────────────┐
│  Layer 2: 노트북 (Control Hub)                       │
│  - YOLO-World 객체 탐지 (실시간, GPU)                 │
│  - OpenCV (캘리브레이션, 삼각측량)                     │
│  - IK 솔버 (Pieper 분해), 안전 검증                   │
│  - 카메라 기반 비상 정지                              │
│  - 역할: "어떻게 할지" 번역                            │
└─────────────────────────────────────────────────────┘
                        ↕ USB Serial (이진 + CRC-16)
┌─────────────────────────────────────────────────────┐
│  Layer 1: Arduino Mega 2560 (Hardware)               │
│  - PCA9685 (PWM 생성)                                 │
│  - VL53L0X ToF (그립 정밀 제어)                       │
│  - 역할: "실제 실행"                                  │
└─────────────────────────────────────────────────────┘
```

각 계층은 독립적으로 동작 가능해야 한다. 특히 **노트북의 비상 정지 판단은 AI 서버 응답에 의존하지 않는다** (네트워크 지연 시에도 안전 보장).

---

## 2. 책임 분리

| 책임 | 위치 | 비고 |
|------|------|------|
| 음성 → 텍스트 | AI 서버 (Whisper) | |
| 객체 탐지 (실시간) | 노트북 (YOLO-World) | 오픈 보캐뷸러리, Detection only, 마스크 없음 |
| 객체 의미 추론 (색·매칭) | AI 서버 (Gemma VLM) | |
| 명령 파싱 → JSON DSL | AI 서버 (Gemma) | |
| 좌표 변환·삼각측량 | 노트북 (OpenCV) | 결정적 작업 |
| 역기구학 (IK) | 노트북 | Pieper 분해 |
| 안전 검증 | 노트북 | DSL 4단계 검증 |
| 비상 정지 감시 | 노트북 (카메라 기반) | AI 서버 비의존 |
| 그립 정밀 제어 | 노트북 (ToF 폐루프) | |
| PWM 신호 생성 | Arduino (PCA9685) | |

설계 원칙: **의미 추론은 위로(AI 서버), 결정적·실시간 작업은 아래로(노트북/Arduino).**

---

## 3. 통신 채널 요약

| From → To | 프로토콜 | 데이터 | 주기 |
|-----------|---------|--------|------|
| AI 서버 ↔ 노트북 | gRPC + Protobuf | JSON DSL, 객체 정보 | 명령당 |
| 노트북 ↔ Arduino | USB Serial 이진 + CRC-16 | PWM 명령, 센서 값 | 50Hz |
| VL53L0X → Arduino | I2C | uint16 거리(mm) | 10Hz |
| 카메라 → 노트북 | USB | JPEG 프레임 | 30Hz |

---

## 4. 핵심 동작 시나리오

```
사용자: "빨간 컵을 책 옆에 놔줘"
   ↓ (노트북: 음성 캡처 → AI 서버로 전달)
음성 인식(Whisper) → 객체 매칭(Gemma VLM) → 의도 파싱(Gemma) → JSON DSL 생성
   ↓ (AI 서버 → 노트북)
DSL 검증(4단계) → 삼각측량 → 좌표 변환 → IK → 안전 검증
   ↓ (노트북 → Arduino, 50Hz)
S-curve 보간 → PWM 매핑 → 모터 제어 → 그립(ToF 폐루프) → 이동 → 놓기
```

## 5. 정량 목표

| 항목 | 목표값 |
|------|--------|
| 그립 정밀도 | ±2mm (콜드스타트 보정 후) |
| 명령 → 그립 완료 | <10초 |
| 객체 인식 정확도 | ≥95% |
| 비상 정지 응답 | <100ms |
| 페이로드 | 150g |
| 팔 길이 | 450mm |
| 자유도 | 6-DOF |
| 제어 주기 | 50Hz |
